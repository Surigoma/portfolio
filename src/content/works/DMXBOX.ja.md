## 概要

DMXBOXは、イベントでの利用を想定した自動照明制御システムです。Raspberry PiとPythonで実装していた旧システム「raspi-DMXBox」を、運用上の課題を解消するためにGoで再開発しました。

設計から実装、テストまで、すべて個人で担当しています。

## 開発の背景

旧システムは実際の運用を見据えるにつれ、次の問題が目立つようになりました。

- 既存のアーキテクチャでは機能追加や保守が難しくなっていた
- 動作環境がLinuxに限定されていた
- 動作中にUSB-DMXデバイスが抜けると、接続を復旧できなかった

これらを個別に修正するのではなく、拡張性と安定性を備えた新しいシステムとして再設計したものがDMXBOXです。

## 技術構成

- Goによるバックエンド
- React / TypeScript / Material UIによるブラウザ管理画面
- HTTP API / TCPによる制御入力
- USB-DMX（FTDI）/ Art-Net / OSCによる出力
- Windows x86-64 / Linux x86-64 / Linux ARM64向けビルド

リリース版では、GoバックエンドがHTTP APIとビルド済みの管理画面を配信します。そのため、1台のPC上で単一のアプリケーションとして運用できます。

## 主な機能

- 512チャンネルのDMX出力
- Fade / Cut / Mute / Unmute操作
- 照明をグループ単位で管理
- Dimmerとホワイトカラー照明のデバイスモデル
- ブラウザからの操作と設定変更
- 設定変更後のモジュール単位でのホットリロード

## 技術的な課題

DMXBOXは、初めてGoを使用して開発した作品です。そのため、言語仕様やGoらしい設計を理解しながら、実際に動作するシステムへ落とし込むことが最初の課題でした。

加えて、次の要件を同時に満たすアーキテクチャの設計に苦労しました。

- 設定ファイルを動作中に再読み込みできること
- USB-DMXデバイスの切断から復旧できること
- 将来の機能追加に対応できること
- イベントでの連続運用に耐えられる安定性を確保すること

## 解決方法

Goについては、実装と調査を繰り返し、動作するコードを継続的に改善することで理解を深めました。

バックエンドは、HTTP、TCP、DMX、OSCを独立したモジュールとして管理しています。各モジュールは初期化・実行・停止とメッセージ処理の共通インターフェースを持ちます。

管理画面から設定を保存すると、設定ファイルを永続化した後、モジュールマネージャーが各モジュールへ再読み込みメッセージを送信します。対象モジュールは `Stop → Initialize → Run` の順に再起動し、プロセス全体を停止せずに新しい設定で状態を再構築します。システムの異常発生時にも、このモジュール単位の再起動を利用できる構成です。

USB-DMX出力では、FTDIデバイスへの書き込みに失敗するとポートを閉じ、次回の出力処理で再オープンを試みます。旧システムで課題だったデバイス切断後の復旧を、出力処理側でも行えるようにしました。

安定性については、Goバックエンドの各モジュールとHTTP APIに加え、フロントエンドの設定画面や操作コンポーネントにもテストを用意しました。正常系だけでなくイレギュラーなパターンも網羅できるよう、コードカバレッジ80%を目標に取り組みました。

## 運用状況

2026年9月に開催されるイベントで利用する予定です。事前検証ではシステムが良好に動作し、ほかのシステムとの連携も確認できています。

## 今後の改善

現在も、開発を進める中で生じた次の設計上の課題が残っています。

- モジュールエンジンの操作性を改善する
- 単方向のみ対応しているメッセージングシステムを双方向化する
- 機能追加によって複雑になった構成を整理する

イベントでの実運用結果も踏まえながら、保守性と拡張性をさらに高めていく予定です。
