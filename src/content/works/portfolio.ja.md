## 概要

自身のプロフィール、技術スキル、制作物をまとめたポートフォリオサイトです。以前使用していたサイトが古くなっていたため、掲載内容と技術構成を見直して再開発しました。

経歴を紹介するだけでなく、ReactやTypeScriptを使ったフロントエンド開発、多言語対応、自動ビルド・デプロイなどを実践する技術サンプルとしても制作しています。

## 主な機能

- プロフィールとSNSリンクの表示
- 経験レベルや用途タグによるスキルの絞り込み
- スキルごとの経験年数、説明、関連制作物の表示
- 制作物のカード一覧とMarkdownによる詳細ページ
- 作品データから関連スキルを自動的に逆引きするデータ構造
- 日本語・英語の切り替え
- ライト・ダーク・システム設定に連動するテーマ切り替え
- 画面幅に応じたレスポンシブレイアウト
- 最終更新日時とビルド元コミットの表示

## 技術構成

- React / TypeScript
- Vite
- Material UI / SCSS
- React Router
- i18next
- React Markdown
- GitHub Actions
- VPS / Cloudflare

## 技術的な課題

### 情報を見つけやすいUI

ポートフォリオには、プロフィール、スキル、制作物など性質の異なる情報があります。情報量を増やしながらも、閲覧者が目的の情報へ短時間で到達できる画面構成を考えることが課題でした。

### コストを抑えた自動デプロイ

継続的に更新するためには、手作業でファイルを配置せず、コードの更新から公開までを自動化する必要がありました。一方で、専用の有料ホスティングサービスへ依存せず、既存のVPSを使って低コストで運用することも要件でした。

## 解決方法と工夫

スキルは経験レベルと用途タグで絞り込めるようにし、詳細ダイアログから説明と関連制作物を確認できるようにしました。制作物は一覧カードと個別ページに分け、概要を素早く比較したい場合と、技術的な詳細を読みたい場合の両方に対応しています。

作品のタイトル、概要、URL、関連スキルは単一のTypeScriptデータ構造で管理しています。スキル詳細に表示する制作例も作品データから逆引きするため、スキルと作品の関連を複数箇所で管理する必要がありません。長い本文は言語別のMarkdownへ分離し、情報量が増えてもコード本体を複雑にしない構成としました。

デプロイでは、`v*`形式のGitタグを起点にGitHub Actionsを実行します。依存関係のインストール、ビルド情報とサイトマップの生成、TypeScriptとViteによる本番ビルド、成果物のアーカイブ、GitHub Releaseの作成までを自動化しています。

GitHub側の更新はWebhookを通じてVPSへ通知され、公開データへ自動的に反映されます。配信にはCloudflareの証明書とCDNを利用し、GitHub、既存VPS、Cloudflareを組み合わせることで追加コストを抑えています。

## デザイン方針

- ライトテーマとダークテーマのどちらでも読みやすいこと
- 日本語と英語で同じ情報へアクセスできること
- プロフィール、スキル、制作物を目的別に探せること
- PCとスマートフォンの両方で操作しやすいこと

装飾を増やすよりも、情報の分類と導線を優先しています。Material UIの共通部品を利用し、テーマや画面幅が変わっても操作方法が大きく変わらない構成にしました。

## 公開・運用

ソースコードとリリース成果物はGitHubで管理し、サイト本体はVPSから配信しています。Cloudflareを経由して証明書とCDNを利用しています。

ビルド時には最新コミットの日時とハッシュをJSONとして生成し、サイト上から現在公開されているバージョンを確認できるようにしています。

## 今後の改善

現在は作品メタデータをTypeScript、詳細本文をMarkdownで管理しています。今後は、コードを直接編集する範囲をさらに減らし、より手軽にプロフィールや制作物を更新できる方法を検討します。
